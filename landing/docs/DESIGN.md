# Computer Use Bridge 落地页

## 本次范围

为已有 `codex-computer-use-mcp-win` 项目制作独立宣传页面，不改动桥接器源代码。用户已明确要求构建。目标受众暂按使用 Qoder、WorkBuddy、DSH 或其他 MCP 客户端的 Windows 开发者设计；这是本次设计假设，不代表已做用户访谈。

主要行动：查看接入步骤并复制适合客户端的配置。无注册、支付、服务端、桌面控制请求或统计脚本。当前本地版本为 `0.4.1-preview.1`，不将其描述为已发布的远端版本。

## 页面结构与文案

1. Hero：让你的 Agent，真正动手。副标题解释第三方模型规划、MCP 桥接、已安装的签名运行时执行。CTA：开始接入。证据行：Windows / MCP / MIT，均来自本地项目。
2. 兼容性横条：列出 MCP 接入目标，不使用品牌 Logo，不声称全部通过实机验收。
3. 三项价值：保留 Agent 的规划权；操作真实 Windows 窗口；执行后重新观察。
4. 大字宣言：你选择大脑。我们接上双手。逐段显示，减少动态效果时直接显示最终状态。
5. 工作链路：第三方 Agent → MCP Bridge → Windows runtime；强调没有嵌套模型。
6. 三步接入：检查环境；本地构建；按客户端复制配置。配置中的绝对路径为示例，明确要求替换。
7. 边界说明：浏览器 URL 核验可能阻止读取；原生页签结果不是后台页签全量清单；输入已发出不等于操作成功。
8. FAQ：支持平台、模型、运行时前提、浏览器限制、应用授权、是否官方项目。
9. 最终 CTA、源码、隐私说明、使用说明。

## 视觉与技术决定

经典 Hero 加段落结构，原因是需要同时解释产品定位、运行方式和接入前提。暖白底、墨黑文字、陶土橙强调色；产品示意成为视觉中心，不用虚构统计或评价填充页面。模拟桌面明确标注，不显示用户真实桌面内容。

查阅 Kumo 和 Astryx Button 文档，采用清晰主次、真实链接、独立焦点状态原则。页面交互简单，无需安装两套 React 组件系统；原生 HTML、CSS、ES modules，以 Node.js 内置 API 生成静态站点。最初考察 Vite，但其依赖审计出现高风险告警，因此移除 Vite 与对应依赖。Geist 本地字体，Phosphor 本地图标。中文使用设备本地可用中文字体回退。

中英文文案集中在 `src/content.js`；用户选择保存在 `localStorage`；默认中文，支持 URL `?lang=en`。语言切换同步标题、描述、导航、示意、配置说明和法律说明页。

布局用 Grid / Flex 和逻辑属性，代码长行仅在代码区域横向滚动，不遮蔽页面溢出。移动菜单用原生 dialog 提供焦点管理；手机全高展示，旧浏览器保留可见导航回退。
